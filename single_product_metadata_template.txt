==================================================================
SINGLE PRODUCT README
==================================================================
This record describes a product that is stored as one copy, with
no variants. Use it when the data is filed as delivered -- or as
processed once -- and there is no second resolution, CRS, or grid
alignment of the same product held alongside it. Feature classes
in a file geodatabase, one-off vector layers, and rasters used
only at their native grid are the usual cases.

Because there is only one copy, this record holds both the
product-level facts (what it is, who made it, how it may be used)
and the geometry of that copy (resolution, CRS, extent, format).
It is the product readme and the variant readme merged into one
file.

Directory layout:

    {product_id}/
    |-- readme.txt              <- this record
    `-- {product_id}_{measure}_{period}.gpkg

If a second resolution, CRS, or grid alignment of this product is
ever added, split this record: move the geographic information,
grid alignment, derivation, and distribution blocks into a variant
readme in a new subfolder, and keep the remaining blocks here as
the product record. See product_metadata_template.txt and
variant_metadata_template.txt.

LAYERS, BANDS, AND FEATURE CLASSES
==================================================================
What each layer, band, measure, or feature class means.

For a file geodatabase or other multi-layer container, record one
entry per feature class or table, and use the Attributes field to
describe its columns. For a raster, record one entry per band.

Layer Count: [Number of layers, bands, measures, or feature
    classes]
    E.g., "3". Use "1" for a single-band raster or a single-
    attribute vector layer.
Layer Structure: [multiband | one file per layer | single layer |
    geodatabase | multi-layer container]
    How the data is organized. E.g., "a single 12-band stack, one
    band per month"; "file geodatabase with 4 feature classes".
Layers: [One entry per layer or feature class]
    For each layer, record the following fields:

    Band: [Band number, layer name, or feature class name as
        labelled in the file. E.g., "Band 1", "MAT",
        "hf_polygons_2021"]
    Measure: [What the band or feature class records]
        E.g., "Mean annual temperature"; "Human footprint
        polygons".
    Geometry Type: [point | line | polygon | raster | table]
    Units: [Units of measurement, or "None" for categorical]
        E.g., "degrees C", "mm", "percent", "None".
    Measurement Scale: [continuous | ordinal | categorical |
        binary]
        Categorical and binary bands require nearest neighbour if
        the data is ever resampled.
    Valid Range: [Minimum and maximum meaningful values]
        E.g., "-50 to 30". Use "Unbounded" if the provider states
        none, or "None" for vector layers. This is the range of
        real values, not the range of the storage type.
    Scale Factor: [Multiplier to convert stored values to units,
        or "1"]
        E.g., "0.1" where the provider stores tenths of a degree
        as integers.
    Offset: [Value added after scaling, or "0"]
    NoData Value: [Value used for missing data, or "None"]
    Attributes: [For vector layers and tables, the field names
        with their types and meanings. "None" for rasters]
        E.g.:

            HF_TYPE     text     Footprint class, see Class
                                 Definitions
            YEAR        integer  Year of disturbance
            AREA_HA     double   Polygon area in hectares

    Description: [What the layer represents and how it was
        measured]
        Anything a user needs in order to read the values
        correctly, including the provider's definition of the
        measure.

    E.g.:

        Band: MAT
        Measure: Mean annual temperature
        Geometry Type: raster
        Units: degrees C
        Measurement Scale: continuous
        Valid Range: -20 to 15
        Scale Factor: 1
        Offset: 0
        NoData Value: -9999
        Attributes: None
        Description: 1961-1990 climate normal, downscaled from
            PRISM.

Class Definitions: [Value-to-class lookup for categorical bands
    and coded attribute fields, or "None"]
    Every code that appears in the data, with its label. Do not
    leave this to a separate file that may be lost. E.g.:

        1   Water
        2   Snow and ice
        3   Rock and rubble

    Where the provider publishes a long class table, record the
    file it lives in and store that file alongside this readme.
